## 怎么用这些样例

- **看共性，不要找同款。** 这 9 例的共同点是：状态多且互相牵制、时序或几何有精确要求、或者多种机制叠在一个完整页面里。再找一个扫雷或生命游戏没有意义，题材重复会被拒（R02）。
- **看题目能写出多少可判定的事实。** 每份 `input.json` 里都有大量具体的数量、顺序、位置、时长。来源作品如果写不出这样的题，就不适合收。
- **旧 5 例里有两例原作含 JS**（135、141），入库时改成了纯 CSS。这说明含 JS 的作品只要核心机制能用 CSS 等价实现，就值得考虑。
- **得分只是佐证，不是筛选方法。** 上表的旧得分来自早期试评，评分口径已废止，只有两个模型，仅用来说明“这类特征确实难”。筛选新候选时只看先验特征，**不要把候选作品交给任何模型试做**。
- 旧库里其余 200 来个案例大多偏简单，见 [existing_cases_catalog.csv](../data_intake/existing_cases_catalog.csv)，不要拿它们当标准。
