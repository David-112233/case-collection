# 成品样例

13 个已入库案例的题目（`input.json`），用来说明“合格的来源作品最后会变成什么样的题”。有 CodePen 来源的案例，链接在 `cases/<案例>/metadata.json` 里，可以对照原作品看。

**样例的比例就是希望的收集比例：网页类最多，CSS 动画类其次，小游戏类最少。**

## 网页类（9 例）

完整的页面或应用界面：区块多、组件多、细节多。这是最想多收的一类。

| 案例 | 是什么页面 | 难在哪 |
|---|---|---|
| case-004-T2 | 电商平台首页 | 多层导航、搜索栏内嵌下拉、大量区块，悬停规则多而细 |
| case-009-T2 | 个人主页与作品集长页 | 整页很长、区块多，十余处悬停反馈各不相同 |
| case-152-T3 | 团队项目看板 | 多列任务卡片，悬停浮起、隐藏菜单展开、焦点保持 |
| case-056-T5 | 移动端天气应用 | 多个元素各自按不同的滚动区间依次变化 |
| case-201-T4 | 手机主屏幕 | 多层嵌套的横向吸附，加粘性标题 |
| case-211-T4 | 旅行摄影相册 | 横向卡片轮播里再嵌纵向图片轮播；吸附到哪一项，标题和图注跟着切换 |
| case-214-T4 | 两周行程概览页 | 吸附、天数编号、当前日指针、周次跳转互相联动 |
| case-213-T1 | 甜品信息图 | 斜切卡片锯齿交替排列，自动编号，五档宽度下几何都要对 |
| case-217-T1 | 品牌官网首屏的等轴测插画 | 137 个元素拼成的静态 3D 场景，各体块的投影位置要一致 |

211、213、214、217 是按现行标准筛出的，另附 `classification.json`，里面有命中特征和证据的写法。

## CSS 动画类（3 例）

多个部件按精确时序协同运动，不是单个元素的循环。

| 案例 | 是什么 | 难在哪 |
|---|---|---|
| case-105-T6 | 圣诞树节日海报 | 星标沿树的轮廓依次点亮，同时全局色相循环变化 |
| case-135-T2 | 多面体形态演化 | 62 个面片在 48 秒内依次演化成四种形态，每个阶段的起止时间都有要求 |
| case-218-T3 | 奔马与慢动作 | 四条腿错峰摆动、关节相连、躯干起伏、头尾摆动要协调；点击后整体进入慢动作 |

## 小游戏类（1 例）

| 案例 | 是什么 | 难在哪 |
|---|---|---|
| case-099-T6 | 滚动驱动的 10×10 迷宫 | 横向和纵向滚动分别移动玩家，逐格停靠，障碍颜色随距离实时变化 |

## 怎么用这些样例

- **看共性，不要找同款。** 这些案例的共同点是：内容和规则多到容易漏、时序或几何有精确要求、或者多种机制叠在一个完整页面里。再找一个天气应用或看板没有意义，题材重复会被拒（R02）。
- **看题目能写出多少可判定的事实。** 每份 `input.json` 里都有大量具体的数量、顺序、位置、时长。来源作品如果写不出这样的题，就不适合收。
- **网页类要的是“难的网页”。** 普通的登录页、定价表、营销落地页库里已经很多，而且对模型太简单。值得收的网页要么体量大且细节密（004、009），要么在完整页面里用了不常见的机制（201、211、214）。
- **004 是早期案例，题材是仿知名电商首页。** 现行标准下“仿制某知名网站”属于常见技术，不再收。看它是为了了解“细节密度”要到什么程度，不要照着找仿制页。
- **218 不是单纯的装饰循环。** 标准里禁收“纯装饰循环动画”，指的是单个元素转圈、闪烁这类。218 这样多部件协调、能看出对错的动画是要的。
- **135 的原作含 JS**，入库时改成了纯 CSS。含 JS 的作品只要核心机制能用 CSS 等价实现，就值得考虑。
- 库里其余 200 来个旧案例大多偏简单，见 [existing_cases_catalog.csv](../data_intake/existing_cases_catalog.csv)，不要拿它们当标准。
- 筛选新候选时只看先验特征，**不要把候选作品交给任何模型试做**。
