# case-253 input 的问题与取舍（2026-11-24，duet）

## 1. 依据

`input.json` 由 GT 写出，外观来自云端浏览器经 raw.githack 打开 GT（提交 `37eb3c0`）在 1280 宽、500 宽的截图与局部放大；按住状态来自自检预览页（提交 `15cb4c2`，位移与 GT 的按下状态相同），因为浏览器工具不能在按住按键时截图。方法和结论见 [review_20261124/static_check.md](review_20261124/static_check.md)。真实按键下的按住截图待本地运行 `review_20261124/shot_gt.py` 补拍。

## 2. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **按键反馈写的是结果**（键帽下沉、顶面低于相邻键帽、侧面被遮住、其他键帽不动、松开立即还原），没写位移数值，也没写 React、类名等手段。“同时按住多个键时每个都按下”是 GT 的实际行为（脚本用集合记录所有按住的键），写进去了；若用户觉得是细枝末节，可以删。
- **没写音效。** 来源按键时会播放一次机械键盘的咔嗒声（外部 mp3），GT 按尊重源码保留了它，但截图无法判定，云端浏览器里也没法核实是否播放。若用户希望把音效作为要求，可在 `motion_constraints` 补一句“按键时播放一次按键音效”，但评测时只能人工听或查代码。
- **写了 BioRhyme 字体名**（Google Fonts 可稳定加载，与 case-232 写 Bitter 的做法一致）。
- **键位写成“与常见数字小键盘相同”并逐排列出**，包括 0 占两格宽、“+”“-”各占两排高；这是部件清单，放在 `functional_requirements`。
- **只写面向桌面宽屏。** 来源不是响应式：500 宽时键盘不缩放，左右被裁、出现横向滚动条。GT 未改，input 也不写窄屏表现。
- **没写进 input：** 具体色值、旋转与倾斜角度（只写“约 45 度、类似等轴测”）、键帽尺寸和间距、外壳的多层阴影参数。

## 3. 档位：T2，待用户确认

GT 唯一的动态是“按住物理键盘的键时对应键帽自身下沉、松开即还原”，不保持状态，也不驱动其他元素（作品里没有显示屏）。协调说明给的判据是“按键只改自身算 T2；若还驱动其他元素就是 T3”，GT 属于前者，所以保持 **T2**，目录名不变。疑点：难度模型的 T2 写的是“悬停只改自身”，这里的触发是键盘事件而不是悬停，没有直接对应的条目；若用户按“由输入事件驱动”从严判，可改 T3。

## 4. 需要用户定的事

1. 档位 T2 还是 T3（见第 3 节）。
2. 音效是否写进 input（见第 2 节第二条）。
3. 自检预览页 `review_20261124/pressed_preview.html` 只是为了在云端看按住状态而做的，不属于 GT；若用户不希望 review 目录里有它，可以删掉。
