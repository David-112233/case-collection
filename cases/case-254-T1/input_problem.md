# case-254 input 的问题与取舍（2026-11-24，duet）

## 1. 依据

`input.json` 由 GT 写出，外观来自云端浏览器经 raw.githack 打开 GT（提交 `1b45045`）在 1280 宽、500 宽的截图与局部放大，方法和结论见 [review_20261124/static_check.md](review_20261124/static_check.md)。

## 2. 作品价值主要在动画（请用户定是否仍收录）

来源是“CSS Lighthouse Scene”，入库时按“关键帧时间动画”暂定为 T2。它的看点有一半在动画：灯塔光束每 20 秒来回扫动、灯室光晕随之明灭、帆船每 100 秒驶过海面、星星闪烁、水波晃动。按准静态要求，GT 去掉了全部动画，定格在来源第 40 秒（选择理由见案例 README），档位改为 T1。

剩下的静态画面仍有前后层次（灯塔与光束盖住天空和月亮、远山交叠、海面盖住山脚、帆船与倒影），但难点从“动画编排”变成了“扁平插画的构图与配色”，对模型来说可能偏易。**按“能做的照做”完成了 GT 和 input，是否仍收录请用户定。**

## 3. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **写了“页面完全静止、没有交互”**，放在 `functional_requirements` 末尾（与 case-252 相同，没有单列 `motion_constraints`）。
- **光束只写了 GT 定格的姿态**：向右射出、越远越宽越淡、延伸出右缘、从月亮上方经过并部分遮住月亮。没有写扫动。
- **帆船写“位于海面中部”**，是 GT 选的静止时刻；来源里帆船的位置随时间变化，这个位置本身没有特殊意义。如果用户觉得这条容易变成凑数的细节，可以放宽为“海面上”。
- **只写配色名和相对位置**，没写色值、像素尺寸、星星和水波纹的数量（来源 60 颗星、30 条波纹，数量不是看点）。
- **只写面向桌面宽屏。** 来源用固定像素定位灯塔，500 宽时灯塔挡住大半画面、帆船被遮住一部分；GT 未改，input 也不写窄屏表现。
- **没写进 input：** 被删的全部动画；灯室光晕在动画里的明灭（GT 里灯室外只有一圈常亮的光晕）；实现手段。

## 4. 需要用户定的事

1. 作品是否仍收录（见第 2 节）。
2. 若收录，是否要改选别的静止时刻（例如光束扫到最长、灯室光晕最亮的第 35 秒）。目前选第 40 秒是因为光束和光晕在这一刻正好是样式本身的值，改动最少。
3. 帆船位置是否放宽（见第 3 节）。
