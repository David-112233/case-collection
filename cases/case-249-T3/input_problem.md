# case-249 input 的问题与取舍（2026-11-24，duet）

## 1. 需要用户定的事

1. **播放态的结束方式（默认照来源）：** 来源点击播放键后会移除点击监听，播放期间再点没有反应，只有音乐播完（`ended`）才自动复原。GT 和 input 照此写。这样“播放态持续多久”取决于音频长度，音频加载失败时页面会一直停在播放态，评测“播完复原”这条要依赖音频能播放。可选：① 维持来源（默认）；② 改成“再点一次停止并复原”，与 case-231 一致、更好判定，但这是给来源加行为，要改 GT。
2. **音乐是否写进题目：** 同 case-231，音乐是点击触发的，属于作品的交互结果，所以保留并给出地址。如果用户认为音频与评分无关，可以从 GT 和 input 里一起删掉，题目其余部分不受影响；同时“播完复原”也要改成别的结束方式（见上一条）。
3. **声波条的静止帧：** 来源播放时 7 条声波条持续起伏。GT 固定在页面载入后 1300ms 那一帧（7 条都可见、中间最长），理由见 README。input 只写“等宽、紧挨、长短不一、中间最长”，不写具体长度。如果用户想要别的帧，或者干脆不要声波条，告诉我即可。
4. **播放键提示闪烁：** 来源播放键侧面的格栅边框每秒由灰蓝渐变到黄色一次，提示可点。GT 去掉闪烁、停在灰蓝色（起点，与周围按键同色），因此 input 没写播放键有黄色边框。若用户希望保留“可点提示”，可以把边框固定为黄色，再在 input 加一句。

## 2. 写进 input 的取舍

- **作品价值部分在动画：** 来源的看点包括拖动旋转视角、播放时的声波律动和插孔圆片旋转。GT 按准静态要求去掉了这些，保留的是开盖内腔的立体层次和点击切换。这一点请用户留意。
- **拖动旋转没有写：** GT 已固定为来源初始视角。
- **写了“两种状态下画面静止，声波条长度固定”：** 理由同 case-231，防止模型照来源加入持续律动，便于判定声波条。如果用户认为这属于从 GT 反推的新要求，可以删掉。
- **没写“切换瞬时完成”：** 去掉仓门 300ms、按键 100ms 的过渡和声波条 1.1 秒的延迟是 GT 的简化，input 只写终态，模型加不加过渡都合规。
- **部件取舍：** 写进了肉眼可辨、能判定的部件（SONY、WALKMAN 标志、窗口、卷轴、顶面按键与 HOT LINE 标签、两个插孔、侧面 MIC 格栅、EJECT 键、播放键、DC IN 3V 插孔）。没写：顶面被挡住只露一角的 “stereo” 标签、侧面极小的 “volume” 字样、磁带内侧的 “MIX TAPE” 标签（渲染不稳定，见 static_check.md）、各面的具体色值和 vmin 尺寸。
- **播放键的位置描述：** 侧面后缘竖排着几个形状相近的格纹按键，播放键是其中顶端斜切的长条。模型画法可能不同，这条在评测时可能需要宽松判定。
