# case-234 input 的问题与取舍（2026-11-24，duet）

## 1. 外部脚本未核验，可能缺失原作交互

`source.html` 引用了相对路径的 `/style.css` 和 `/script.js`，离开 CodePen 后加载不到；GT 删掉了这两个引用。没有去 CodePen 或其他地方抓取 `/script.js` 的内容。

按以下三点推断它在 CodePen 上也不存在、原作没有脚本交互（**推断，未核验**）：

- 两个引用在作者粘进 HTML 面板的一整份文档里，像是作者本地文件的写法；样式已全部内联在 `<style>` 里。
- CodePen 整页输出会把 JS 面板代码作为内联 `<script>` 放在 `</body>` 前，`original_srcdoc.html` 里没有这样的脚本，JS 面板很可能是空的。
- 作品标题是 “Polaroid Camera In CSS”，作者注释指向的也是一篇纯 CSS 教程。

因此 input 写成“完全静止、无交互”，档位按 GT 判定为 **T1**。**两者都待用户确认**：如果用户知道原作有交互（例如点快门出片），input 的 `motion_constraints` 和档位都要重写。

## 3. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **写成正视图**：相机正面朝向观者，不倾斜、无透视。来源就是平面正视插画，“凹面”“凸起”都由明暗表现。
- **部件名**：计时器、感光孔、电源钮的名字取自源码的类名（`timer`、`sensor`、`power`），画面上只是三个小圆钮，所以 input 同时写了外观（浅色小圆钮、深色小圆孔、黑色圆钮），评测按外观判定。
- **没写进 input**：相机的具体尺寸（固定 570×470，不随视口缩放）和所有色值，只写相对位置、相对大小和颜色名，与 case-224、227、230 样板一致；两个空 `div`；`aria-label`（不可见）；窄屏下相机向右溢出、出现横向滚动（来源没有响应式处理，写进去等于要求模型复现缺陷，所以写“面向桌面宽屏”）。
- **写了 `motion_constraints`“完全静止、无交互”**：这是来源原貌，不是 GT 简化的结果（前提见第 1 节）。样板 224、227 没写这一段；若用户认为不需要，可以删掉。
- **颜色只写颜色名**：背景“极浅的青蓝色”（`#9CDCE0`–`#9CD4E0`）、上半机身“近白色”、下半机身“近黑的深灰色”、拨钮“橙色胶囊、黄色圆钮”。

## 4. 作品本身的难度提醒

入库评语写的是“正面单物体，倾斜空间弱于 Switch”。按推算，难点集中在用渐变和阴影画出写实的同心镜头、凹陷的闪光灯与取景器、凸起的按钮，部件位置关系都是平面上的上下左右。可判定的条目多为“部件在某位置、某颜色”，写实质感（凸起、凹陷）判定起来比较主观。是否仍收录，请用户看截图后定。
