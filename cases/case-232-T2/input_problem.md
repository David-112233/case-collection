# case-232 input 的问题与取舍（2026-11-24，duet）

## 1. 外观描述由 CSS 推算，已用云端浏览器核对（2026-11-24）

**核对结果：** 仓库公开后，经用户同意用云端浏览器经 raw.githack.com 在 1280 和 500 宽下渲染（方法与结果见 [static_check.md](review_20261124/static_check.md)）。下表各项全部与渲染一致，**翻折方向确认是向观者**，input.json 不需要改。三个标题实际都是一行。375 宽没法在云端核对（工具最小 500 宽），input 也没对窄屏提要求。

原先由 CSS 推算的各项：

| input 描述 | 推断依据 | 风险 |
|---|---|---|
| 右半边“向观者方向翻折”，外侧边缘比折线处更高、在画面上变窄 | 右半边 `rotateY(-50deg)`，绕自身中心（即卡片竖直中线）旋转，父级 `perspective: 1000px`；按矩阵外缘 z≈+138px，投影后外缘约在中线右侧 134px、高约 139px | 翻折方向是这道题的核心，**最需要核对** |
| 露出的浅绿底面、白色外框仍在原位 | 右半边下面是 `.articles__link`，背景为页面同色浅绿、2px 白色实线边框，不随悬停变化 | 外框在截图里是否明显待核对 |
| 箭头“位于露出的区域内，比平时略向右偏” | 箭头是链接的 `::after`，16×16、右距 24px，悬停时透明度 1、右移 12px，约在卡片左缘 332–348px；翻折后右半边外缘约在 314px | 若推算有误，箭头可能压在翻折面上 |
| 三张卡片一行、整组大致居中、相邻之间窄缝 | 1280 宽下网格 3 列、每列 328px，卡片固定 360px，卡片间约 16px，`ol` 默认左内边距使整组偏右约 20px | 偏右 20px 是否算“大致居中”由用户定 |
| 标题“可换行” | 标题可用宽约 320px，Bitter 粗体 16px 下前两条标题可能折成两行 | 渲染中三个标题都是一行；input 未规定行数，“可换行”保留以免限制模型 |

## 2. GT 去掉悬停过渡（默认做法，待用户确认）

来源的翻折有 0.5s 过渡，箭头有 0.25s 延迟后右移。用户同意“点击触发的一次性过渡去掉时长、直接到终态”；悬停过渡没有单独说明，我按同样处理，GT 悬停时直接到终态。input 与 case-228 一致，**只写终态，不写“瞬时完成”**，也不要求有过渡，所以模型加不加过渡都合规。如果用户希望 GT 保留来源的悬停过渡，只需把三处 `transition` 加回，input 不用改。

## 3. 写进 input 的取舍

- **没写进 input：** 所有具体尺寸、色值和翻折角度（只写相对关系、颜色名和“向观者翻折”，与 case-224、227、228 一致）；`cursor: pointer`（与核心无关）；Google Fonts 里未用到的 Bebas Neue、Righteous；左右两半在折线处重叠 1% 的实现细节。
- **写进了 input：** 字体 Bitter（GT 唯一使用的字体，可判定）；“不悬停时页面静止，没有持续或循环的动画”（与 case-228 同理，防止模型加入场动画；来源的入场动画本来就没有关键帧、不可见）。如果用户认为这一句属于从 GT 反推的新要求，可以删掉。
- **“页面面向桌面宽屏”：** 来源不是响应式，375 宽下卡片排成一列、页面横向溢出约 65px（推算）。所以 input 不对窄屏提要求，与 case-227 的写法一致。
- **不可键盘聚焦：** 卡片的 `<a>` 没有 `href`，来源如此，GT 未改；input 不写聚焦效果。

## 4. 档位：维持 T2，有一个疑点

悬停时变化的是被悬停卡片自身的右半边和它自己的箭头伪元素，指针离开即还原，按难度模型 v2.1 判 T2。疑点是箭头“平时不可见、悬停时出现”，如果把箭头看成“被唤出的其它元素”就会落 T3。我的默认是 T2：箭头是卡片链接自身的 `::after`，属于卡片的一部分，类似“卡片 hover 上浮”而非“hover 唤出 tooltip”。

## 5. 需要用户定的事

1. GT 是否保留来源的悬停过渡（第 2 节，默认去掉）。
2. 是否保留“没有持续或循环的动画”一句（第 3 节）。
3. 档位 T2 还是 T3（第 4 节，默认 T2）。
4. 选题顾虑：AGENTS 选题标准不收“单组件演示”。本作是三张同款卡片加一个悬停翻折，接近单组件演示；它已在首轮审核中被用户选中，我照常加工，提请用户留意。
