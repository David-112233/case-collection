本环境无法渲染 GT（装不了 Chromium，见 [review_20261124/static_check.md](review_20261124/static_check.md)）。作品是纯 CSS、无脚本，几何都是固定像素，位置和数量可以直接从样式算出，风险主要在“画面看起来像什么”。下列描述需要在本地运行 `review_20261124/gt_selfcheck.py` 后对照截图核对：

| input 描述 | 推断依据 | 风险 |
|---|---|---|
| 扬声器格栅是“水平开槽，后面透出深棕色大圆形喇叭，上有两条竖向筋条” | `.speaker` 六层背景：8px 一循环的米白条（开槽之间的格栅）、#897866 的圆形径向渐变（半径约 80px）、x=50 与 x=120 两条 6px 竖条 | 圆在开槽中是否清楚可见待核对；若看不出是喇叭，改成“深色圆形区域” |

## 2. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **写了少量具体尺寸：** 机身约 960×260 像素、扬声器约 180×200 像素。作品是固定像素的写实插画，比例是外观的一部分，只写“横向长条”无法判定比例是否对。case-228 只写相对关系；如果用户希望各案例统一不写像素，可以改成“宽约为高的 3.7 倍”“扬声器高略大于宽”。
- **颜色只写颜色名，不写色值**（与 case-224、227 样板一致）。八个窄按钮的颜色顺序写了，因为它是可判定、非实现手段的外观事实。
- **数量与排列写得很具体：** 17 白键、12 黑键、黑键分组 2、2、3、2、3 以及无黑键的四处分缝。这正是作品的核心考点（黑白键叠压），与真实 PT-1 从 G 到 B 的琴键排列一致。
- **标签文案按源码写成小写**（mode、volume、tone、tempo、one key play），源码没有大写变换。
- **tempo 标签的位置：** 来源里 tempo 下方没有专门的推子，标签落在窄按钮组中段上方，input 照实写位置，没有补一个 tempo 控件。
- **没写进 input：** 控制条纹理每一段的位置；各黑键反光角度的差异；黑键下端两角的微小高光；扬声器左右边缘的暗化；标签边框颜色；所有色值。这些要么太细碎、要么难以判定，写进去会诱导拆细条件。
- **没写“没有动画、没有交互”：** 来源本来就没有，功能需求里写“静态插画”已经说明，不另加禁令。
- **窄屏：** 机身固定 960px 宽，来源不做窄屏适配，375 宽视口会横向溢出。input 写“面向桌面宽屏”，不对窄屏提要求（与 case-227 一致）。

## 3. 档位

GT 与来源都没有任何动态，按难度模型 v2.1 为 T1，与入库暂定一致，未改名。
