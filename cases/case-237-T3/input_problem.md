# case-237 input 的问题与取舍（2026-11-24，duet）

## 1. 外观依据

默认状态和音量刻度依据 GT 源码和云端浏览器截图写出（见 [review_20261124/static_check.md](review_20261124/static_check.md)）。**播放状态没能在云端浏览器里点出来**，“唱头落到唱片外圈靠右下”“指示灯变红”是按源码推算的，待本地截图核对。

## 2. 写进 input 的取舍（选了最保守的做法）

- **没写进 input：** 被去掉的动画（唱片旋转、唱臂缓慢扫动、箭头跳动）；具体尺寸、色值；实现手段（Tone.js 和各个合成器的音色、节拍等都不写，只写“一段循环的合成摇滚乐，由页面自行生成，不需要音频文件”）；电源键上的手形光标。
- **写进了 input：**
  - “两种状态下画面都是静止的，唱片不旋转，唱臂没有持续摆动，箭头也不跳动”。这是准静态 GT 的设计结果，与 case-228、231 的写法相同；如果用户认为这一句属于从 GT 反推的新要求，可以删掉。
  - 标签文字写成“COOL BAND ALBUM”。源码里是逐个字母沿圆周排列（倒序写在 HTML 里），渲染后按顺时针读出这三个词。
  - 唱臂转动角度写成“约 17 度”，这是源码点击后直接写入的值，作为“落到唱片上”的可判定依据；如果觉得太细，可以只写“转到唱片上，唱头落在外圈”。
- **音乐能否判定：** 音频无法从截图判定，评测时可能只能检查“点击后有声音”或记 UNRESOLVED，与 case-231 相同。
- **音量刻度只改指示线：** 来源点击刻度不改变音量，GT 保留原样，input 也只写指示线转动，没写“调节音量”。

## 3. 需要用户定的事

1. 作品的动态价值主要在播放时唱片旋转和唱臂扫动，准静态后只剩开关状态切换和刻度点击。是否仍收为 T3 案例。
2. 是否保留“唱片不旋转……箭头也不跳动”这一句。
3. 是否保留音乐要求（见第 2 节）。
