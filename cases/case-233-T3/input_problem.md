## 2. 仍未核实的

- **触屏端列表：** 云端浏览器是鼠标设备，只显示了桌面端 7 条列表。触屏设备显示 3 条列表是按 `data-mobile` 推断的。
- **面板开合有没有过渡：** 两张截图里卡片宽度差了约 5px，可能有很短的过渡或悬停效果，无法确认。若有，按准静态要求要在 GT 里加一条覆盖规则去掉时长，会新增样式，先问用户。
- **没写进 input 的细节：** 盘子转了 12°；外侧面靠近缺口处的两三个褐色小圆斑；盘面右侧蛋糕阴影形成的锯齿形明暗边（来源同样如此）；所有具体尺寸和色值（只写相对关系和颜色名，与 case-224、227 样板一致）。

## 3. 写与不写的取舍（选了最保守的做法，待用户确认）

- **写进了 input：** “画面静止，没有持续或循环的动画，蛋糕不自动旋转”。这是准静态 GT 的结果，不写的话模型照来源做成自动旋转也合规，会让视角类规则无法判定。若用户认为这是从 GT 反推的新要求，可以删掉。
- **写进了 input：** “面板里的文字只是展示内容，不要求实现其中列出的手势”。GT 去掉了 `camera.js`，面板却仍列着拖拽、滚轮、双击等手势；不说明的话，模型会以为要实现这些手势。

## 4. 需要用户定的事

1. **说明面板留不留。** 面板列出的手势在 GT 里都不起作用了。我按“尽量尊重源码”保留了链接和面板（档位因此为 T3）。另一种做法是把链接和面板一起删掉，题目只剩静态蛋糕，档位改为 T1，input 里与面板有关的句子也一并删掉。这个作品的价值在静态的立体蛋糕和切面夹心，两种做法都不影响主体。
2. 是否保留第 3 节两句由 GT 设计带来的说明。
