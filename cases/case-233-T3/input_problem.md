# case-233 input 的问题与取舍（2026-11-24，duet）

## 1. 最大的风险：画面依赖的外部文件一个都读不到

作品的场景容器、相机变换、`--px` 尺寸单位、页面背景图层、说明面板的全部样式写在 `shadowshahriar.github.io` 上的 `starter.css`、`3d.css`、`howto.css` 里，蛋糕和盘子的质感来自同站的七张纹理图。本环境的代理拦截该站点，也没有浏览器，所以**这些文件的内容和渲染效果都没看到**。GT 还去掉了 `camera.js`，同样读不到它，无法确认它是否在初始化时写入画面必需的值。本地运行 [review_20261124/gt_check.py](review_20261124/gt_check.py) 之后，先看 GT 默认截图和来源截图是否同一视角、同一大小，再核对下表。

## 3. 写与不写的取舍（选了最保守的做法，待用户确认）

- **没写进 input：** 盘子转了 12°（看不出来）；蛋糕一块侧面上的三个浅色小圆点装饰（太细碎，位置取决于视角）；切面、侧面上的细部阴影渐变角度；所有具体尺寸和色值（只写相对关系和颜色名，与 case-224、227 样板一致）。
- **写进了 input：** “画面静止，没有持续或循环的动画，蛋糕不自动旋转”。这是准静态 GT 的结果，不写的话模型照来源做成自动旋转也合规，会让视角类规则无法判定。若用户认为这是从 GT 反推的新要求，可以删掉。
- **写进了 input：** “面板里的文字只是展示内容，不要求实现其中列出的手势”。GT 去掉了 `camera.js`，面板却仍列着拖拽、滚轮、双击等手势；不说明的话，模型会以为要实现这些手势。

## 4. 需要用户定的事

1. **说明面板留不留。** 面板列出的手势在 GT 里都不起作用了。我按“尽量尊重源码”保留了链接和面板（档位因此为 T3）。另一种做法是把链接和面板一起删掉，题目只剩静态蛋糕，档位改为 T1，input 里与面板有关的句子也一并删掉。这个作品的价值在静态的立体蛋糕和切面夹心，两种做法都不影响主体。
2. **第 2 节的推断** 要本地渲染核对后才能确认，尤其是缺口方向和切面条带顺序；有误就按截图改写 `layout_constraints`。
3. 如果本地发现去掉 `camera.js` 后画面塌了（相机初值是脚本写的），需要把来源截图的相机值写成静态 CSS，这会在 GT 里新增样式值，先问你再做。
4. 是否保留第 3 节两句由 GT 设计带来的说明。
