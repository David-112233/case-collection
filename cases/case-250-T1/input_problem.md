# case-250 input 的问题与取舍（2026-11-24，duet）

## 1. 写进 input 的取舍

- **作品看点：** 宽屏下横幅左右交错、圆片向上压住相邻横幅一角的叠盖关系，以及断点切换后的版式变化。input 把宽屏和中等宽度两套版式都写了，因为“响应式”是来源的主题（标题即 Responsive infographic banners）。
- **断点数值写成“约 625px”“约 480px”：** 这是来源的两个断点，属于结果（在什么宽度下版式变化）。如果用户认为写断点太细，可以改成“宽屏”“较窄的视口”。
- **文字全部给出：** 标题、说明文字、编号、图标字符都是 GT 里的内容，评测要核对，所以逐条写明。
- **颜色只写颜色名：** 红、金黄、青绿、灰褐；不写色值，也不写渐变停靠点。
- **字体只写“无衬线”：** 来源字体栈是 Trebuchet MS、Verdana，云端浏览器里都没有，GT 实际显示为默认无衬线体；指定字体会出现“input 指定字体但 GT 环境显示不了”的情况，所以不写字体名。
- **没写的：** 横幅具体尺寸（30em×10em）、圆片直径、平移 15%、±0.1° 旋转、投影的模糊半径等实现数值；225px 以下字号缩小的断点。

## 2. 需要用户留意或决定的地方

1. **来源在中等宽度下有文字被切的瑕疵：** 600、500 宽时，圆片在左的 02、04 横幅，标题图标和说明文字最左几个字母被切掉（见 static_check.md）。来源如此，GT 没修。input 要求显示完整说明文字，GT 在这一宽度下自己就会不满足。可选：① 维持来源，评测时中等宽度只看版式不看文字完整（默认）；② 在 GT 里做最小修复（例如去掉中等宽度下那 0.1° 的旋转），但这会改动来源样式。请用户定。
2. **窄屏（480px 以下）版式：** 见下文第 3 节。
3. **选题顾虑：** 这是一个“信息图横幅”组件，四条结构相同，接近单组件演示；难点在叠盖层次与响应式断点。它已在追加审核中被选中，我照常加工，提请用户留意。

## 3. 窄屏版式（已核对，2026-11-24）

来源在 480px 以下把 `--narr` 设为 1，利用 `var(--narr, …)` 取到无效值，让横幅的网格、圆角、固定高度和圆片的底色、阴影、尺寸全部失效：横幅变成占满宽度的直角色块，编号退化为白色大号数字放在左上，标题和说明文字依次排在下面。云端用 `frame_view.html?w=450` 核对，渲染与上述一致（见 static_check.md）。这套版式写进了 input 的最后一段。它是来源有意做的窄屏退化，但看起来比较“素”；如果用户只想考宽屏和中等宽度，可以删掉这段。
