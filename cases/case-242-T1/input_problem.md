# case-242 input 的问题与取舍（2026-11-24，duet）

## 1. 最大的问题：GT 在云端浏览器里渲染不完整（待本地复核，请用户定）

经 raw.githack 用云端浏览器打开 GT，房间有大块白色缺口：1280 宽下后墙只画出一部分、天花板和右墙前端有白色楔形、地板与墙脚之间有白带；500 宽下地板几乎整块缺失。按 CSS 几何推算这些面应当完整。入库时 dot 也记录了“白色大块区域与视口裁切需复核”。详见 [review_20261124/static_check.md](review_20261124/static_check.md)。

可能原因（都未证实）：
1. 云端浏览器没有 GPU，对多块大面积 `preserve-3d` 平面的绘制出错。
2. 作者外部引用的 `codepen.io/zenete/pen/eYLjgaq.css`（及 `.js`）没有加载成功，而它可能提供了房间需要的样式（例如根字号）。本环境的代理拒绝 codepen.io，读不到它的内容。
3. 来源本来就是这样。

**默认做法：** input 按源码几何描述完整的房间，没有把白色缺口写成要求；GT 不做任何修补。需要在本地用有 GPU 的 Chrome 运行 `review_20261124/gt_check.py`（无头和 `--headed` 各一次）确认。若本地也有缺口，这个 GT 就不能作为评测参照，建议改用别的案例，或由用户决定是否允许修补。

## 3. 写进 input 的取舍

- **写了“画面静止，吊扇不转动”。** 这是准静态 GT 的设计结果。来源吊扇是持续旋转的，不写的话模型照来源加上旋转也合规，但会让扇叶位置类规则无法判定。如果用户认为这是从 GT 反推的新要求，可以删掉。
- **没写进 input：** 作者外部脚本可能注入的签名元素（画面上没看到）；窄屏（400px 以下）作者设的吊扇静止姿态；各部件的 rem 尺寸、色值和阴影参数。
- **吊扇只写“整体较小”**，没写具体尺寸。

## 4. 档位

来源唯一的动态是吊扇旋转和扇叶明暗，GT 去掉后无动态、无交互，已由 T2 改为 T1（目录名 `case-242-T1`）。

2. 是否保留“画面静止，吊扇不转动”一句。
