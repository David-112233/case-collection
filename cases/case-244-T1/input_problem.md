# case-244 input 的问题与取舍（2026-11-24，duet）

## 1. 外观已按渲染核对

GT 经 raw.githack.com 在云端浏览器打开，在 1280 和 500 宽截图，并放大四组交点逐一核对（见 [review_20261124/static_check.md](review_20261124/static_check.md)）。`input.json` 里的排列、间距、颜色和八个交点的上下关系都与截图一致。

## 2. 写进 input 的取舍

- **套扣次序按 GT 逐个写出，没有写“与奥运会标志一致”。** 来源是用四分之一弧的叠层做出的套扣，次序是否与官方五环完全一致没有核对；写成“与官方一致”既不可判定，也可能与 GT 不符。按 GT 写出八个交点后，每一条都能从截图直接判定。
- **“页面面向桌面宽屏”**：来源五环总宽固定约 735px，不随视口缩放，窄于这个宽度的视口会横向溢出（500 宽截图可见滚动条，绿、红两环被截）。与 case-230 相同，input 只面向桌面宽屏，没有写尺寸数值，也没有要求窄屏适配。
- **没写的：** 具体像素尺寸和色值（只写相对关系和颜色名，与 case-224、227 样板一致）；下排环圆心相对上排两环中点略偏左（黄环圆心离蓝环更近），这是来源定位的副产品，写进去会变成细碎条件。
- **“页面完全静止，没有动画和交互”**：来源本身就是纯静态，这是如实描述，不是 GT 的简化。

## 3. 需要用户定的事

1. **题目难度偏低。** 入库评语已写“复杂度明显低于参考案例”。纯 CSS 或 SVG 画五环并做出套扣，对强模型可能不难，主要扣分点只有八个交点的上下关系。是否保留由用户定，我按保留继续做了。
2. 套扣次序是否要改成官方五环的次序（需要先核对官方标志）。我的默认是按 GT 写，不改。
