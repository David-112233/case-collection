# case-246 input 的问题与取舍（2026-11-24，duet）

## 1. 外观已按渲染核对

GT 经 raw.githack.com 在云端浏览器打开，在 1280×800 和 500×800 截图，并放大书架和底层查看（见 [review_20261124/static_check.md](review_20261124/static_check.md)）。视角、五层 × 24 本、颜色顺序、地板和两面墙的位置、露出的藏青格纹背景都与截图一致。颜色顺序另按源码逐本核对过：120 本书的书脊色相每本相差约 3°，正好绕色相环一圈，最高通道值为 #50，所以都很暗。

## 2. 来源自带的渲染瑕疵（GT 未改，待用户定）

**地板穿过最下层。** 地板这块三维平面与书架相交，渲染时有一块浅粉褐色的地板盖在最下层中部的书前面，最下层左端的书架腿下方也露出背景格纹而不是地板。这是来源的三维数值造成的，GT 只删了样板，所以完全相同。

- **默认做法：** GT 不改；input 不描述这块瑕疵，也不要求“地板不得遮挡书架”，只写“书架立在地板左缘附近”。
- **可选：** 调整地板或书架的位移让二者不相交。这会改来源的三维数值，是否这样做请用户定。

## 3. 写进 input 的取舍

- **写了“每层 24 本，共 120 本”和颜色的整体顺序**：这是作品的核心，数量可数、顺序可看。没写每本书的色值和高度（来源由 SCSS 随机数编译成逐本规则）。
- **写了“场景不随视口缩放、不出现滚动条”**：来源全部用 rem 定尺寸，`main` 绝对定位并 `overflow: hidden`。500 宽时书架两端被裁掉。input 面向桌面宽屏。
- **背景格纹露出的位置** 写成“书架左后方的一条斜带和画面左下角”。这是左墙和地板没有拼合留下的，属于来源的构图，所以如实写入；如果用户觉得这是瑕疵而不是设计，可以改成只写“背景为藏青色菱形格纹”。
- **没写的：** 书架内部 `.plane` 的绿色底面（被书架和地板挡住，画面上看不到）；normalize.css（作者选用的样式重置，对画面影响很小）。
