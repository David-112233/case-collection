# case-228 input 的问题与取舍（2026-11-24，duet）

## 1. 渲染核对结果（2026-11-24，云端浏览器经 raw.githack.com，1280 与 500 宽）

原先按 CSS 推算的视角、可见面、投影方向、默认配色都与渲染一致，`functional_requirements` 和 `layout_constraints` 未改。详细记录见 [review_20261124/static_check.md](review_20261124/static_check.md)。

`motion_constraints` 按实际渲染改了发光模式的描述：

| 原写法（推算） | 现写法（核对后） | 原因 |
|---|---|---|
| 机身变为半透明的浅蓝白色，四周带蓝色外发光 | 机身正面变为浅灰蓝色，侧边和端面变为白色，机身轮廓带蓝色外发光 | 实际正面偏灰蓝、侧边和端面是白色；看不出半透明 |
| 屏幕和滚轮变为半透明 | 删去 | 渲染时屏幕和滚轮被正面部分或全部盖住（来源自带的问题，见第 3 节），这一句在 GT 上无法判定 |
| 滚轮中央按钮变为半透明蓝色 | 滚轮中央按钮变为浅蓝色 | 实际呈浅蓝色 |
| （无） | 充电接口和耳机孔变为蓝色 | 渲染中明显可见 |
| 机身下方出现一团柔和的圆形蓝色光晕 | 机身周围出现一团柔和、暗淡的蓝灰色光晕 | 实际光晕很暗、偏蓝灰，围在机身四周 |

## 2. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **没写进 input：** 顶端端面的 HOLD 开关（存在于源码，但默认视角下朝向背面、看不到，无法判定）；鼠标移到滚轮上显示手形指针（源码有 `cursor: pointer`，与题目核心无关，避免增加细碎条件）；所有具体尺寸和色值（只写相对关系和颜色名，与 case-224、227 样板一致）。
- **写进了 input：** “两种模式下画面静止，没有持续或循环的动画”。这是准静态 GT 的设计结果，不写的话模型照来源加上悬浮动画也合规，但会让位置类规则难以判定。如果用户认为这一句属于从 GT 反推的新要求，可以删掉。
- **没写“切换瞬时完成”**：去掉 0.6s 过渡是 GT 的简化，不是作品要表达的效果，所以 input 只要求切换后保持状态，不限制有无过渡。
- **“页面不出现滚动条”**：来源 `body` 为 100vw×100vh 且 `overflow: hidden`，作为可判定结果写入。

## 3. 需要用户定的事

1. **发光模式下屏幕和滚轮被机身正面盖住**（来源本身就有，任何静止帧都一样）。默认做法：GT 不改，input 不描述这两处在发光模式下的样子。可选的修正是把发光模式下屏幕、滚轮离机身正面的距离调大一点，但这会改动来源的三维数值，是否这样做请用户定。
2. 是否保留“没有持续或循环的动画”这一句。
3. 窄屏时滚轮上的图标字号不随视口缩小，显得拥挤；input 未对图标大小提要求。
