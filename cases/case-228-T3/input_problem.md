# case-228 input 的问题与取舍（2026-11-24，duet）

## 1. 外观描述按源码推断，未经渲染核对

本环境无法渲染 GT（装不了 Chromium，jQuery、图标脚本被出站代理拦截，见 [review_20261124/static_check.md](review_20261124/static_check.md)）。`input.json` 中下列描述是从 CSS 推算的，需要在本地运行 `review_20261124/gt_check.py` 后对照截图核对：

| input 描述 | 推断依据 | 风险 |
|---|---|---|
| 视角：正面朝上方、长轴从左上斜向右下、底端在右下更近 | 场景 `rotateX(309deg) rotateY(-694deg)` 即绕 X 轴 -51°、绕 Y 轴 26°，按矩阵推算各面法向 | 方向判断错误会让多条规则失真，最需要核对 |
| 可见左侧长边和底端端面，看不到另一条长边和顶端端面 | 各面 `backface-visibility: hidden`，按法向推算朝向 | 同上 |
| 投影向机身左侧偏移 | `.shadow-shape` 在机身局部坐标中 `translateX(-3vw)`，落在机身左侧长边一侧 | 画面上的偏移方向待核对 |
| 发光模式机身为“半透明浅蓝白色” | 面色 #cccccc 或 #ffffff、透明度 0.8，叠加 #2374c6 的 `mix-blend-mode: screen` | 实际颜色可能更偏白或更偏蓝 |
| 发光模式“机身下方一团柔和的圆形蓝色光晕” | `.light-scene` 为 22.5vw 圆、蓝色、透明度 0.2、模糊，并叠一层黄色 screen 混合 | 光晕是否可见、偏蓝还是偏黄绿待核对 |
| 四个图标显示为黑色小图标 | 图标是 all.js 注册的自定义 SVG，字号 0.32rem（约 5px） | 若 all.js 加载失败图标不显示；图标极小，评测时可能难以判定 |

## 2. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **没写进 input：** 顶端端面的 HOLD 开关（存在于源码，但默认视角下朝向背面、看不到，无法判定）；鼠标移到滚轮上显示手形指针（源码有 `cursor: pointer`，与题目核心无关，避免增加细碎条件）；所有具体尺寸和色值（只写相对关系和颜色名，与 case-224、227 样板一致）。
- **写进了 input：** “两种模式下画面静止，没有持续或循环的动画”。这是准静态 GT 的设计结果，不写的话模型照来源加上悬浮动画也合规，但会让位置类规则难以判定。如果用户认为这一句属于从 GT 反推的新要求，可以删掉。
- **没写“切换瞬时完成”**：去掉 0.6s 过渡是 GT 的简化，不是作品要表达的效果，所以 input 只要求切换后保持状态，不限制有无过渡。
- **“页面不出现滚动条”**：来源 `body` 为 100vw×100vh 且 `overflow: hidden`，作为可判定结果写入。
