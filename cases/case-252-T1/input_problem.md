# case-252 input 的问题与取舍（2026-11-24，duet）

## 1. 依据

`input.json` 由 GT 写出，外观描述来自云端浏览器经 raw.githack 打开 GT（提交 `1c969df`）在 1280 宽和 500 宽的截图与局部放大，核对方法和结论见 [review_20261124/static_check.md](review_20261124/static_check.md)。375 宽没有截（浏览器工具最小 500），但 500 与 375 都在同一个窄屏版式内（切换点为 775px）。

## 2. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **写了宽屏、窄屏两种版式。** 作品标题就是“Responsive banners”，两种版式的切换是它的主要看点，而且都是 GT 里确实有的静态结果，所以都写进 `layout_constraints`。没有写切换点的具体宽度（775px），只写“桌面宽屏”和“手机宽度”。**若评测只用桌面视口，窄屏一段无法判定，可以删掉，请用户定。**
- **只写配色名（橙红、青绿、深棕、草绿）**，没写来源的 8 个色值；渐变方向写成“上浅下深”，与截图一致。
- **字体只写“无衬线”**，没写 Trebuchet MS、Verdana：来源指定的这两种字体在不少环境里没有，云端浏览器显示的就是回退字体；写进 input 会让条件依赖评测环境。
- **写了“页面完全静止、没有交互”**，放在 `functional_requirements` 末尾，没有单列 `motion_constraints`（与 case-230、234 的写法不同，那两例单列了一段）。来源本身没有任何动态。若用户希望统一成单列一段，可以挪过去。
- **没写进 input：** 横幅宽度 768px、高度、间距 24px、圆标直径、斜切 45° 等具体数值；外框左下角被标签和圆标盖住、看不见的径向暗影（来源里有这层渐变，但宽屏下被斜切标签遮住，画面上看不到）；prefixfree 等实现手段。

## 3. 档位

GT 无任何动态、无交互，仍为 **T1**，目录名不变。

## 4. 需要用户定的事

1. 窄屏版式那一段是否保留（见第 2 节第一条）。
2. 作品的难点主要是斜切标签压住彩色细线、圆标的圆环与暗弧、胶囊外框的多层渐变，条件数量不会多。是否足够难，请用户判断。
