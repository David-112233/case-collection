# case-230 input 的问题与取舍（2026-11-24，duet）

## 1. 外观已用云端浏览器渲染核对（2026-11-24）

用项目的云端浏览器经 raw.githack 打开提交 `ab4e41c` 的 `ground_truth.html`，在 1280 宽和 500 宽各截图一次（浏览器工具最小宽度 500，375 做不了），截图只用于查看、未入库。方法和结论见 [review_20261124/static_check.md](review_20261124/static_check.md)。原先由 CSS 推算的各条核对结果：

| 原 input 描述 | 核对结果 | 处理 |
|---|---|---|
| 白色纸片略向左上偏移，向右上方翘起，越往右越高 | 成立。白色纸片比蓝色字母明显偏左，左端略高，越往右越高；笔画还略向右倾 | 保留，补“笔画略向右倾” |
| 蓝色只在下边和右边露出楔形窄边，越靠右越宽 | 部分成立。下边是从左往右变宽的楔形；右边是宽度大致均匀的窄边；G、E 等字母内侧的右边和下边也露蓝 | 改写，分开描述右边和下边，补内侧边缘 |
| 蓝色为明亮的天蓝色 | 不成立。露出的蓝色大部分被阴影压暗，呈偏深的钢蓝色，只在靠上的少数位置较亮 | 改为“偏深的钢蓝色，只在靠上处较亮” |
| 灰色阴影略向下、向右下倾斜，在下边和右边透出暗边 | 阴影主要表现为蓝边下方一圈柔和的灰色模糊影，倾斜看不出来 | 改为“蓝边下方一圈柔和的模糊暗影”，删去倾斜 |
| 白色纸片与背景几乎同色，带极浅的白到浅灰横向渐变 | 成立，右侧略灰；纸片边缘有一圈很淡的灰色柔影，轮廓在白底上可辨 | 保留，补“边缘很淡的灰色柔影” |
| 五个字母在一行内居中 | 成立。实际总宽约 470px（原先估算 590px 偏大），1280 和 500 宽都在一行 | 保留 |

额外发现：此前在本机用 headless 浏览器试过 375 宽（那批截图已按要求删除，未提交），宽度不足约 490px 时字母换成两行，第一个 N 的白色纸片层和阴影留在第一行、与字母本身错开，页面横向溢出。来源相同，GT 未改。input 只面向桌面宽屏，所以不影响 input。字体在云端浏览器中显示为常规粗体无衬线体，与 input 的写法一致。

## 2. 写进 input 的取舍（选了最保守的做法，待用户确认）

- **写成三层叠字**：功能里写“白色纸片、露出的蓝色同形字母、灰色阴影”三层。这是画面上能看到的组成，不是指定伪元素或 `transform` 等手段；如果用户认为这已经接近实现描述，可以改成只描述最终观感。
- **颜色只写颜色名**（纯白、偏深的钢蓝色、白到浅灰），没写来源的 `#32A8E0`（渲染后被阴影压暗，画面上主要是约 `#257EA8` 的深蓝），也没写字号 128px、倾斜角度、偏移像素，与 case-224、227 样板一致。若想让颜色可严格判定，可以把色值加进去。
- **字体只写“粗体无衬线”**，没写 Helvetica。来源只写了本地字体名 Helvetica、无回退，各系统显示不一；写进 input 会让字体条件依赖评测环境。
- **写了 `motion_constraints`“完全静止、无交互”**：来源本身就没有任何动态，这一句描述的是作品原貌，不是 GT 简化的结果。样板 224、227 没写这一段；如果用户认为不需要，可以删掉。
- **没写进 input**：标题上方空白的具体高度（只写“明显的空白”）；`rotateY`、`translateZ` 带来的几乎不可见的变化；来源里被浏览器忽略的无效声明。

## 3. 作品本身的难度提醒

入库评语已指出“关系较单一，难度不应因视觉效果而夸大”。作品的可判定点集中在一个效果上（白色纸片翘起、蓝边露出、阴影），条件数量会很少。是否仍收录、以及这几条外观描述是否足够区分模型，请用户定。

## 4. 需要用户定的事

1. 颜色是否要写色值；如果写，写来源的 `#32A8E0` 还是画面上看到的深蓝。
2. 窄屏（约 490px 以下）错位是否要在 GT 里修（例如给两个伪元素加 `top: 0`）。目前按“尊重源码”未修，input 只面向桌面宽屏。
3. 是否保留 `motion_constraints` 这一句。
4. 作品是否仍收录（见第 3 节）。
