## 3. 难度标准（拟登记为决策）

8 条特征：H1 多状态耦合、H2 一处触发多处联动、H3 精确时间编排、H4 新特性、H5 几何/3D 精度、H6 计算内容、H7 大体量完整布局、H8 多机制组合（定义见扩量方案 §3.3）。

**分档阈值建议：**

| 档 | 可用特征 | 入库阈值 |
|---|---|---|
| T1 | H4（如容器查询、subgrid、anchor 定位等静态新特性）、H5、H6、H7 | 命中 ≥2 项，且其中必须有 H5 或 H7 |
| T4 | H2、H4（如 `scroll-state()` 查询、`::scroll-marker`/`::scroll-button` 新式轮播）、H7、H8 | 命中 ≥2 项 |
| T2/T3/T5/T6（后续批次） | 全部 | 命中 ≥3 项 |

**一票否决：** 单组件演示、纯装饰循环动画、一条 CSS 规则即可复现的作品。

**禁止：** 用正式被测模型的得分挑题；看到模型输出后改题。

每例在 `screening.csv` 记录命中的特征编号和对应源码位置，作为可复核证据。

## 4. JS 改造规则

**可改造收入**，需同时满足：

1. JS 不是核心机制（如只做统计埋点、主题切换按钮、装饰随机数），或核心功能可用 CSS 等价实现（如点击切换 → checkbox/`:target`，滚动监听 → `animation-timeline`）；
2. 改造后仍达到 §3 阈值；
3. 改造后在浏览器中核对，主要视觉与机制保持。

**JS 不作为自动淘汰条件。** 脚本只标注 JS，含 JS 的作品与纯 CSS 作品一样进入第 4 步由我逐个判断。旧流水线 `run_codepen_pipeline.py prepare` 遇到 JS 会标 `blocked_javascript` 并跳过，本批不用它来筛选；改造后的无 JS 版本再交给它做构建检查。

**拒收：** JS 承担核心逻辑且 CSS 无法等价（如复杂游戏规则、Canvas/WebGL 绘图、网络请求、随机生成内容）。

**留痕：** `metadata.json` 记录 `js_policy: removed | replaced`、被删或替代的功能说明、改造前后哈希；来源标为 `derived`（改编自原作品，保留原作者和 MIT 归属）。
