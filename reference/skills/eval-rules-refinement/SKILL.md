# eval_rules 双层精炼

目标是得到**来源明确、计分单位合理、条件可判定**的规则草稿。先确定 Requirement 的边界，再拆其 Mandatory Evidence。**条件就是扣分单位**（DEC-038）：每条失败的条件按轻 0.5 / 中 1 / 重 1.5 扣分，同一 Requirement 内累计；所以条件粒度直接影响分数，一个可独立失败的事实写一条，既不为增加扣分拆细，也不把能独立失败的事实合并。本方法来自多例审核与修订，修订稿不是 gold 标准，已用于改进的案例也不能证明对新案例的泛化效果。

## 来源与范围

- 先读仓库 [AGENTS](../../../AGENTS.md)、[评分细则 v6](../../docs/scoring_rubric_v6.md)、[任务定义 v5.2](../../docs/TASK_DEFINITION_v5_2_synced.md) 和目标案例当前 `input.json`；按需读已有草稿与审核意见。Requirement 来源是 `input.json` 加基本常识（DEC-037）：常识条目只限 input 已要求元素的基本可用性，须标明 `source: common_sense` 及理由，交用户审核；任务定义提供项目统一输出禁令。`business_background` 主要给语境，不能单独支撑新增计分要求。
- 草拟语义规则时不从 GT、模型输出或既有分数反推条件。草稿可描述语义 target、动态动作和前置状态；具体选择器、GT 锚点、容差、执行脚本和模型输出验证属于后续阶段。结构检查通过不等于可执行或已获批准。
- 用户明确只读或仅要求提炼方法时，不改案例；授权生成或修订案例时，遵守指定的覆盖/留版方式，记录所用 input 版本。修订先比较来源哈希及有据可查的字段变化：把需求变化导致的同步与同一需求下的生成错误分开，同步受影响的条件、采样、依赖、`input_contract`、测量政策、审核备注和哈希，清除已经失效的待澄清项；不要只替换一个数字。若本轮获授权读取或验证了 GT，更新来源与验证说明，不能继续声称从未读取或尚未验证。旧输入的输出不自动适用新规则。
- 审核报告是反馈，不是新的需求来源。逐项核对原字段及评分规范，再判断采纳、否定或待裁定；用户授权按报告修改不等于逐项语义已获确认。缺少旧版本时说明使用了哪些原始记录或报告引文，不把另一套旧规则冒充修改前版本，也不把已修订稿自动当成正确答案。

## 第一层：划分 Requirement

1. 逐段列出 input 中明确的**可失败事实**，记下原字段、对象、状态/触发、量词与范围词，以及它属于页面区域、独立元素、对象关系、动态子目标还是禁令。特别核对“整张”“每个”“仅限”“主要”“不超过”、精确与近似数值。指名标准规则时检查其必要核心约束；若有多个变体或未定义目标状态，留待澄清，不补唯一玩法。只在 input 明确顺序或顺序属于该机制的必要语义时强制先后关系；“文本分别为”或审核报告要求排序，本身不足以把列举顺序变成页面顺序。
2. 对每一候选项问：它能否独立失败、独立报告？是否属于不同对象、关系、触发或状态区间？不同对象/关系或独立动态能力倾向拆开；同一对象的颜色、尺寸、文案等属性留在一条 Requirement 内。Relation 应有明确参与对象与关系目标，不把页面区域之间的关系、区域内部的关系和区域自身尺寸混作一条；Region 仍可聚合自身整体属性，不按 CSS 属性机械拆分。大量同质成员按组计一条，但“每个成员”不能只验一个代表后宣称全组通过。静态类型使用评分细则 v6 的 `region` / `element` / `relation`；同质组属于 `element`，组范围写入描述或 target，不另造 `element_group` 大类。
3. 给每个事实指定**唯一责任 Requirement**。区域与子元素、元素本身与元素间关系、静态存在与动态效果分开：控件存在不证明点击生效，状态表示完整不证明调度正确，当前输入被采用不证明计算正确。先把共同范围词展开到明确涵盖的对象；跨对象统一属性若单列，各对象不再重复拥有该属性，分归各对象时逐项核对接收条目，避免删重后漏掉成员。响应式条件按具体对象及视口归属，不用笼统的“全页文字适配”重复覆盖子对象。用最小错误反例区分“重复设置同一检查事实”与“上游失败实际阻断下游独立需求”；后者按DEC-029分别判FAIL，不因共同根因合并Requirement或豁免下游。归属结论须落实到最终条件正文，不能只靠通用去重备注保留互相重叠的必过谓词；也不能仅凭同坐标或同一画面假定同根因。静态结构不补动态映射的标记或实现层，完整状态组也不等于必须预渲染同等数量的 DOM 层。
4. 对不明来源、input 内部矛盾或会改变需求语义的候选项标为待裁定；只有用户确认后才改 input 并纳入计分。先检查具体对象/状态说明能否作为一般定性描述的兼容例外，不能把一般描述再强加于明确特例；若两项规格确实不能兼容，仍报告冲突。指定文案与功能机制冲突时按原文核对，不从文案补行为。限制“额外可交互入口”时，区分可点击控件与题目明要的 hover 感应区域；范围含糊时只强制确定对象，其余留作审核问题。可实现性疑点单独记录，不靠 GT、业务背景或实现能力补写或降低题目要求。

若 input 要求多个效果共用驱动或整体叙事，先区分**共享触发/位置映射、局部效果、已有阶段顺序、整体替代**。只有能独立失败时才分别计分，不为每个动画固定加一条驱动 Requirement。局部效果缺失归其子目标；已有各效果共同受错误驱动时，驱动事实只归一次，独立方向、幅度或阶段错误仍可另判。相邻条目用“只有静态外观错”“只缺一个效果”“效果俱在但共同定时推进”“只有辅助进度提示”作有来源的反例，落实到条件正文；辅助提示的存在不等于核心叙事被替代，症状相似也不证明共同根因。

若 `motion_constraints` 为空，不为填满 D2 虚构动态 Requirement；按现行缺维度公式检查权重。

## 第二层：拆分 Mandatory Evidence 条件

- 对每条 Requirement，先写出 description 的明确事实，再配可判定条件：**目标、适用状态/视口、预期结果与主要证据方式**。静态存在条件避免以实际动作生效作为判据；动态文案/符号要对应当前对象、状态或下一步操作，不能由页面别处的图例、候选文本并列或隐藏分支代替。抽样、依赖、归因放在元信息，不把“去抽样”“由另一条检查”单独写成 mandatory。独立可判断的事实拆成条件，数量不固定；因为条件是扣分单位，同一事实不能在两条条件里各写一次，也不能为同一对象的同一缺陷准备多条可同时失败的条件。
- 先确认条件在需求允许的状态中是否可观察。对象本体、当前显隐和布局位置是不同事实：当前没看见既不证明对象缺失，也不证明分支显隐正确。对 input 明确存在的对象，先单独列本体事实，再为各分支显隐条件写明具体本体前置及唯一归属，不能在本体条目中只放“显示/隐藏”谓词来代替存在性；这一分工须落在正文和依赖，不能仅靠公共备注。关系不能靠拼接不同状态/视口坐标判断。两文本未要求同时可见时，不补共同显现或保留占位义务；只有 input 明确保留位置时才检查占位保持。若合法状态仍无法比较，记录题目语义待澄清。能力回退先列 input 明确的分支条件与基础前提，不以浏览器品牌、页面自述或本次效果成败判断能力；未定义能力集合时不自行指定唯一 CSS API。回退只替代其声明的能力/结果，不自动取消独立时间动画或其他仍适用要求；本 Skill 只定义语义分支与证据需求，不实现能力探针。
- 区分 DOM/无障碍、几何、计算样式、截图视觉与交互状态。若要求整对象可激活（如整卡链接），检查其可感知主体的命中区域，不能由局部文字链接代替；input 未给的 URL 不补造。“内容保持边界内”同时核对完整可见与不越界，不能让 `overflow: hidden` 裁掉内容后通过。跨对象色值只由一个归因点负责；渐变、半透明发光判主色与层次，不要求每个像素等于不透明色号。视觉综合词落实为 input 指定的可见层次；近似尺寸不发明倍率或阈值，明确的 `≤500px` 等边界不能写成“约”。
- 动态条件明确前置、动作、结果及来源明确的保持/恢复。对有状态交互，逐项核对正常态、非法动作、终局和重置中 input 要求的结果及例外；一种常态反馈的例外不自动放宽按压等另一种反馈。重开/重置先明确操作对象与范围，再核对 input 初态及其语义要求清除的旧状态、结果提示和可继续操作性，不能只看入口或归位，也不扩大成全页复位、随机化、模式复位或精确计时字符串。涉及“保持/沿用”的属性时，比较操作前后是否改变，区分原错误延续与操作另行引入的错误；不能仅因状态名不同就再次归因。只说 hover/focus 不自动要求离开后恢复；“可切换且保持”不意味着再次触发不得改变。按住瞬态与释放后状态分开，click 终帧不能代替按压证据，单张终帧不能证明过程。未限定的释放后常态不补具体符号；不能仅因它恰与按住时相同就推断反馈失效。
- 区分**条件的量词**与**探测方案**：“每个成员”“每个明确枚举的状态”不等于所有成员必须同时激活或穷举所有组合。覆盖明确成员/状态的计划须能发现遗漏，不能以少量代表宣称全组通过；也不能把最低示例步数、便利路径或可选高值扩展变成 input 未要求的必过规格。条件适用域与采样域对齐，包括仍适用的边界/例外状态。input 给出坐标或算法时可作独立数学展开并核对来源；未给时只提出探索/比较方法，不从 GT 补坐标。算法链区分初态传递、结果计算、播放与计数联动，分别检查其独立事实及有需求依据的反例。
- 过程条件还要说明阶段之间的适用范围：input 要求始终单一完整离散画面时，中间停留位置也适用，不能只看整帧端点；明确允许连续滑动、局部画面或交叉淡化时则按其要求。只要求离散状态不自动补“任何时刻一帧”的强限制。按需描述中间位置和切换边界的语义覆盖，不冻结步长或阈值。对有限滚动区间，逐成员记录所需阶段及需求允许的可达范围；未探测到不等于不适用，若应有阶段因实现失败而不可达，按具体上游事实归因，不能默许省略。用户停止输入与驱动位置停止不同；吸附仍在改变位置时，位置驱动的变化不能仅因此判为自动播放。独立成员不等于异源素材；input 要求不同插画画面时，不能只改编号，明确允许复用时仍允许同源。
- 把显示格式、数值顺序、计时节奏分开归因：例如两位 `99→00` 的补零由显示条件检查，递减序列由动态条件检查，不能由约 100 秒时长臆造精确每步秒数。依赖按DEC-029（`model-dependency-fail/1.0`）：已确认模型前置对象/行为失败实际阻断下游mandatory条件时，上下游均判FAIL，各按自己的严重度扣分（DEC-038），暂不做根因去重。写明具体前置事实、成员及分支；整条Requirement FAIL不自动阻断所有下游，仍可观察的条件继续检查。评测器定位、驱动、采证、环境/API问题或原因不明仍为UNRESOLVED；不得仅因定位器没找到就认定模型缺失。该政策已获用户确认，不再把依赖阻断聚合列为未决，也不增设新状态；草稿仍须经过后续执行准备和审核才能用于评分。

## 门禁与归因

- 分清项目通用输出契约与 `input.forbidden` 的题目专属禁令。新案例/新轮次按 [输出契约 v2](../../docs/output_contract_v2.md)（DEC-048）允许 JavaScript、外部字体及图片，字体加载样式表可外链；页面 CSS 和 JS 代码仍内嵌。不得沿用旧版一概禁止 JS/字体/图片的门禁，也不要把普通导航链接当作外部素材。仅检查当前契约或案例明确限制的资源与行为；历史冻结版本保留原政策。通用模板不写具体案例的字体、文案、布局或“不添加动画”范围。Gate与条件、多个Gate或多条条件记录同一直接违规事实时只扣一次；同一检查事实不在多条条件或多个Requirement重复设置。模型依赖阻断按DEC-029例外分别计FAIL，不能以旧“同根因只扣一次”备注豁免下游；草稿的去重备注不等于聚合器已实现。

## 复核与交付

沿“input 事实 → Requirement → 条件”检查覆盖，再反向核对来源、静态三分类、唯一归属、成员/状态覆盖、触发与例外、依赖分支、Gate overlap 和编号引用。以相邻条目的最小错误反例检查是否重复归因，并核对条件与采样是否同域；发现条件无法安放时回到第一层。语义修订后再核对 description、条件正文及相关政策/摘要是否仍陈述同一版本，不能一处已澄清而另一处仍待澄清。此阶段只设计语义目标与证据类型，不执行 GT 绑定、浏览器采证、容差冻结或正式评分。结构校验不证明语义无误；语义复核不证明评分器可靠或机器评分贴近人工。

案例修订只改授权的版本化草稿及必要的 input/状态记录；做定向 JSON、ID、来源版本和引用校验，简短报告尚待用户裁定与尚未执行的事项。不默认生成多份报告，不自行写 `accepted`，不把草稿质量等同于人机评分一致性。

可按需对照三例的当前精炼草稿：004 展示关系归属与逐成员依赖；116 展示单设备多属性条件和按住操作；153 展示独立结果状态、共同呈现与来源待裁定后的恢复。示例中的 ID、数量与目录版本不是新案例模板，历史草稿的旧依赖阻断口径不覆盖DEC-029。

复审争议或维护本 Skill 时，可查[语义复核参考](references/semantic-review.md)：159/115/190 的前后条件、需求变更、反馈处置、指导缺口与定向复核。它是可追溯的改进依据，不是初稿生成模板或已批准答案。

遇到隐藏对象关系、能力回退、共享滚动驱动或中间状态覆盖时，可查[滚动与能力分支复核](references/scroll-and-capability-review.md)：105/109/070 的版本依据、反馈处置、适用边界及本次验证限制。
