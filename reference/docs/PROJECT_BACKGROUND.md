# 项目背景（采集者必读）

> 2026-11-24 更新：2026-11-16 起（DEC-048）**JavaScript、外部字体和图片已放开**，本文旧的“纯 CSS”表述已改。输出限制以 [输出契约 v2](output_contract_v2.md) 为准。
本页帮助采集者理解“什么样的作品值得收”。筛选的硬标准在 [data_intake/README.md](../../data_intake/README.md) 第 6 节，这里讲标准背后的原因。

## 1. 这个基准测什么

给模型一份自然语言需求（`input.json`），让它生成**单文件 HTML** 的页面（CSS 内嵌；JavaScript、外部字体和图片允许，具体案例的禁令以该案例 input 为准）。早期版本曾禁止 JavaScript、只考纯 CSS，任务定义 v5.2 里的相关限制已被输出契约 v2 取代。完整定义见 [任务定义 v5.2](TASK_DEFINITION_v5_2_synced.md)。

`input.json` 有五段：业务背景、功能需求、布局约束、动效约束、禁令。它只写“要什么效果”，不写“用什么 CSS 实现”。成品样例见 [examples/](../examples/)；完成态样板见 [examples_finished/](../examples_finished/)。

每个案例最终包含三样东西：

| 文件 | 作用 | 谁写 |
|---|---|---|
| `input.json` | 给模型的题目 | 依据来源作品的实际效果人工编写 |
| `ground_truth.html` | 参考答案，证明题目可以做到 | 以来源作品为基础，只做必要的最小修改，并自测 |
| 评测规则 | 把 input 拆成一条条可判定的条件 | 依据 input 起草，用户审核后冻结 |

分工：采集者（dot、duet）找到合适的**来源作品**；用户选中并入库后，由 duet 在 `cases/` 里写 input、GT 和规则草稿，用户在本地审核。所以选作品时要想着后面几步能不能做下去。

## 2. 评分怎么做

评测在无头 Chromium（Playwright）里打开模型生成的页面，在多个视口宽度下（如 1280 和 375）检查每一条条件，分静态（D1）和动态（D2）两个维度。能从样式、几何、DOM 直接读出的事实由程序判，定性条件交给视觉模型判。每条不通过的条件按严重度扣分。

这决定了什么作品“可评”：

- **效果要确定。** 同一页面每次打开结果一样。依赖随机数、当前时间、网络请求内容的作品不可用。
- **效果要能被驱动和观察。** 自动化能做的操作是悬停、点击、聚焦、键盘、滚动。只能靠触摸手势或拖拽才能触发的效果很难验证。
- **效果要在 Chromium 里成立。** 只有 Firefox 或 Safari 支持的特性不可用。
- **可判定的事实越多越好。** 位置、尺寸、状态、时序、数量、文字内容都能判。纯粹“好看”而没有结构可言的作品，写不出多少能判的条件。

## 3. 为什么只要难题

早期 56 例试评中，DeepSeek 平均 9.27 分，40 例满分，“困难组”得分反而比“简单组”高。题目太简单，分不出模型好坏。现有案例里有不少因此不合格。

所以本轮采集的目标不是凑数，而是找**现有模型大概率做不好**的作品。两类作品被证明拉得开差距：

- 多机制组合的完整页面：如吸附加状态查询加锚点定位加计数器的行程页。
- 精确约束多的动画或几何：如多阶段精确时间编排的 3D 几何、多部件协调的角色动画。
- 多状态互相牵制：如纯 CSS 扫雷。

**题材上，用户希望多收网页类、其次 CSS 动画类、少收小游戏类。** 这个基准的定位是前端网页生成，小游戏虽然难，但离真实的前端工作远，库里也已经有不少。小游戏不是不收，只是每轮最多报 1 例。

反过来，两类作品看着复杂但对模型不难，用户已明确拒收：

- **技术常见。** 网上教程和示例极多，模型见过无数遍：普通轮播、单行吸附列表、目录高亮、流媒体仿制页、报纸杂志网格版面。
- **答案可检索。** 内容是公开的固定知识，模型搜一张图就能照做：如元素周期表。

判断时多问一句：**一个训练语料里见过大量 CSS 教程的模型，会在这里的哪一步出错？** 说不出具体出错点的作品，多半不够难。

注意：**禁止用被测模型的实际得分来挑题**，也不要把作品喂给模型试做。难度只按先验特征（H1—H8）判断。

## 4. 来源作品要能改成案例

来源作品不会原样入库，而是经过“源码 → input → 参考答案”改写。以下情况会让改写变难或失去意义，筛选时要在备注里写明：

| 情况 | 影响 | 处理 |
|---|---|---|
| 外部字体、图标字体、外部图片 | 现已允许，原样保留 | 备注写明；缺图不是拒收理由，但不能把没看到的写成已核验 |
| 外部图片、视频是视觉核心 | 评分和审核都看不到关键内容 | 备注写明，通常不推荐 |
| 真实品牌、真实人物、名人照片 | 版权与肖像问题 | 拒收（X1），或确认可换成虚构内容 |
| 国旗等特殊 emoji | 评测环境可能没有字形 | 备注即可，是否替换在加工阶段由 input 决定 |
| 作品文字里直接写出实现代码或技巧说明 | 会向模型泄露做法 | 可改成中性文案，备注即可 |
| 抓到的页面没有样式 | 无法得到原作视觉 | 拒收（X1） |
| 效果依赖很新的浏览器特性 | 需确认评测用的 Chromium 支持 | 备注特性名称 |

## 5. 已有哪些题材

[dedupe_index.csv](../dedupe_index.csv) 列出主仓库全部 227 个案例的档位、来源链接和一句话业务背景。用途有两个：

- 避免题材重复。库里已有的题材（登录页、营销落地页、数据看板、定价表、各类卡片悬停等）不必再找。
- 了解现有案例偏简单到什么程度。前 200 例大多是普通页面加少量动效，新案例应明显比它们难。

链接级别的去重由抓取脚本自动完成，题材级别的重复要靠采集者自己看这张表。

## 6. 采集目标

目标 450 例，T1—T6 各 75。当前最缺 T1（纯静态）和 T4（滚动吸附类）。T4 难题本来就少，可以接受缺口，不降标准。只从 CodePen 公开作品里找。采集初期的方案原文见 [扩量方案](../history/DATA-001-expansion-plan-20260928.md) 和 [B1 工作方案](../history/DATA-001-workplan-B1-20261002.md)（口径已过期，只供追溯）。

历史通过率约 3%（早期 265 个候选里 7 个建议入库）。大量拒收是正常的，不要为了交差放宽标准。
